## Goal

Three query shapes that are easy to write compile to a full scan of a stored
relation. Each one put a full scan inside MindGraph's exclusive ingestion write
in November 2026: 55–157 s per page before the queries were rewritten by hand
and a CI lint was added to stop them coming back
(`mindgraph-rs/scripts/cozo-query-lint.sh`, cases 2 and 3; the second trap has
no lint). Compile these shapes to keyed access in the engine, with identical
results, so no consumer needs the rewrites or the lint.

| Shape | Example | Plan today | Target |
|---|---|---|---|
| T1 trailing unification | `*node{uid}, uid = $u` | `load_stored :node` with the unification as a post-filter: full scan | `stored_prefix_join` on `uid` |
| T2 key plus non-adjacent value column | `*edge{from: f, to: t}, *node{uid: t, tombstone_reason: 'deleted'}` | `stored_mat_join`: the whole `node` relation is materialized | `stored_prefix_join` on `uid`, then a per-row check of `tombstone_reason` |
| T3 equality with a rule-bound variable | `f[x], *node{uid: u, name: n}, u == x` | cartesian `stored_prefix_join` plus `filter eq(u, x)`: full scan per left row | `stored_prefix_join` on `uid` |

## Decisions

**D1 — Hoist trailing equality unifications (T1).** Extend
`push_equality_filters_to_bindings` (`reorder.rs:59`) to also move a
`NormalFormAtom::Unification` with `one_many_unif == false` to the front when:
its variable is generated by a positive stored atom; its expression is a
constant (parameters are constants by this stage); and the constant is
non-numeric, or numeric with the same variant (`Int` or `Float`) as the
declared type of every stored column the variable binds. Column types come
from the relation metadata the pass already reads for key arity
(`resolve_key_arities`, `reorder.rs:433`); the `SchemaView` grows from key arity
to key arity plus column types. Anything else stays where it is. The existing
`==` conversion gains the same declared-type rule, so `t == 5` on an `Int` key
becomes keyed too.

**D2 — Seek on the leading key run and check the rest (T2).** Replace the
`join_is_prefix` gate for positive stored joins with: sort the right-side join
positions; the *seek run* is the longest run `0..n` among them, cut at the key
length (at the plain key length for validity and bitemporal relations). If the
seek run is non-empty, use `prefix_join`; every join pair outside the seek run
is checked on each found row, as `point_lookup_join` already does. An empty
seek run keeps `materialized_join`. `::explain` keeps the label
`stored_prefix_join` and shows the residual pairs in `joins_on`. Negated joins
(`neg_join`) keep today's gate in this batch; they are listed for batch 2.

**D3 — Turn variable equalities into join keys (T3).** In the same pass, a
predicate `eq(u, x)` where `u` is bound only by a stored atom later in the body
and `x` is bound earlier is rewritten by substituting `x` for `u` in that atom
(and keeping `u` as an alias through a front unification so the head still
binds it), provided every stored column `u` binds has a declared non-numeric
type. Numeric and `Any` columns are left alone; `op_eq` and storage identity
differ there.

**D4 — No switch.** Results are unchanged by construction (each rewrite is
restricted to cases where `op_eq` and storage identity agree), so there is no
`:pushdown off` option. `:reorder written` continues to control only the join
reorder.

## Invariants

1. Every rewrite returns exactly the rows the unrewritten plan returns, on all
   backends, including for `Int`/`Float` cross-type values and `Null`.
2. A query that compiled before compiles after; a query that failed with an
   unbound-variable error still fails.
3. No seek prefix includes a validity or transaction-time column.
4. Plans stay stat-free and deterministic.

## Acceptance tests

- Plan shapes (SQLite, `tests/planner_shape.rs` style, empty relations): T1, T2
  and T3 compile to `stored_prefix_join`; the brace-bound and binding-first
  forms are unchanged; `planner_baseline.json` changes only where a plan
  contained one of the three shapes, each change reviewed.
- Result equivalence on mem, SQLite and RocksDB, for each shape: string keys,
  `Int` and `Float` keys with matching and cross-type constants, `Null`
  values, composite keys bound partially, validity and bitemporal relations,
  and a negated atom (unchanged plan).
- The numeric fence: `t = 5.0` and `t == 5.0` on an `Int` column still return
  the `Int(5)` row; `t = 5` on an `Int` column becomes keyed.
- MindGraph's lint fixtures (`mindgraph-rs/scripts/fixtures/cozo-query-lint/`)
  replayed as plan-shape tests: every flagged line compiles keyed.
- A benchmark of the existence check `*node{uid}, uid = $u` at 10k, 100k and 1M
  rows: flat with size after the change (it grows linearly today).
- `cargo test -p mnestic --test fork_regressions --test matjoin_regression
  --test planner_shape` and the LSQB tier in `planner-guard` pass.

## Layering ruling

Engine only. MindGraph needs no change; its lint cases 2 and 3 can become
advisory once production runs the release, which is a MindGraph decision.

## Rejected alternatives

- **Cost-based choice between prefix and materialized join.** The engine has
  no statistics, and the plans are stat-free by design. A full-key match is
  always a point lookup, and a partial-key prefix already uses prefix joins
  today when it is exactly `0..n`, so D2 only extends the existing rule.
- **Converting numeric equalities without the declared-type check.** Changes
  results for cross-type values (verified current state).
- **A warning instead of a rewrite.** Warnings move the burden to every
  consumer; the shapes are the natural way to write the queries.
