# Mnestic 0.19 planning

Updated November 8, 2026 following the owner's release decision. The selected
correctness and governed-transaction scope is approved for release with the
measurement caveats below. Final publication checks and registry confirmation
remain separate delivery evidence; this document does not assert publication.

## November 8 release decision and measurement scope

The owner authorized release on November 8 after independent experiment review
recommended proceeding with the core improvements and documented latency caveats.
Optional consumer automatic exact-routing changes are deferred. No additional
benchmark campaign is required for this decision. The final runtime is
`d6b9b5bffa5408b8e274a447c5f9f6fa791f3b75`; the release commit adds publication
metadata and documentation, which still require final artifact verification.

The focused comparison is `3a8815a2` → `d6b9b5bf`, **both 0.19 builds**. It does
not quantify the full 0.18-to-0.19 upgrade cost. Package dependency locks differ,
which limits source-only causal attribution. Three synthetic input seeds and two
measurement windows do not establish production generality.

The original R2 engine campaign stopped at its fixed two-hour deadline with
23 of 24 graphs complete; its consumer arm completed. A separate follow-up built
both fresh RocksDB/seed1236/dimension1536 graphs. The coverage view uses 22 original
graphs plus that fresh pair, excluding both originals for that identity. The
original campaign remains incomplete; no new graph is paired with an old graph.
Independent review verified 393 copied raw-file hashes, graph identities,
percentiles and flagged intervals. The measured cases included 2,400 acknowledged
writes with successful exact index/hash checks, 14,400 successful first probes,
12 clean rollbacks and 8,640 matching same-graph reader comparisons. These
observations do not establish universal integrity or exact ANN recall.

| Write p95, 600 writes per package/backend | Before | After | Change | Paired 95% interval for increase |
|---|---:|---:|---:|---:|
| RocksDB | 38.015 ms | 39.200 ms | +3.1% | -1.902 to +4.826 ms |
| SQLite | 46.123 ms | 51.545 ms | +11.8% | -2.701 to +345.198 ms |

SQLite's large wall-time tail is concentrated in seed1235; the other two seeds
improve. Wall-wait/runtime effects are an inference, not a proven cause or evidence
that the slowdown is harmless. The combined view flags 11 of 192 selected read
cells (about 2.2–6.3 ms increases), with positive intervals in two SQLite1536/
adversarial1% filtered cells (ef100 and ef400); nine intervals cross zero. One of
64 E3 cells flags with an interval crossing zero. These are diagnostic cases,
not a production frequency mix.

The separate one-seed, two-graph RocksDB/1536-dimension window has five flagged
read cases, which pooling must not obscure:

| Case | Before p95 | After p95 | Paired 95% interval for increase |
|---|---:|---:|---:|
| Random 10%, exact | 249.50 ms | 288.57 ms | +3.12 to +50.80 ms |
| Random 1%, exact | 26.20 ms | 30.41 ms | -2.50 to +8.36 ms |
| Random 0.1%, filter ef100 | 38.55 ms | 44.80 ms | +0.64 to +8.11 ms |
| Adversarial 10%, exact | 248.22 ms | 287.94 ms | +6.62 to +47.59 ms |
| Adversarial 1%, exact | 25.89 ms | 30.39 ms | -0.89 to +5.18 ms |

The roughly 16% exact-scan increases and filtered-ANN increase remain release
caveats; these intervals do not establish cross-seed generality. The source delta
adds repair scratch reuse and an FTS lifecycle shortcut rather than new scanning,
scoring or ANN expansion, but that does not prove it is unrelated to the slowdown.
Do not advertise a general speedup, a uniformly small upgrade penalty, or exact
ANN recall. Pre-0.19 HNSW indexes need explicit rebuilds, with backup, maintenance
time and search validation; preserving paths also adds work to mutations and can
reject writes at local degree/work limits.

Raw evidence remains in the local release archive (not linked as a public download):
`release/0.19-qualification/d6b9b5bf/final-measurement-r2/` contains `RESULTS.md`,
`engine-analysis.json`, `consumer-analysis.json` and raw manifests; the separate
pair is retained under `../final-measurement-tail/`. This tracked summary records
the comparison boundaries and accepted caveats without relabeling that evidence
as a complete released-0.18 campaign. The optional consumer strategy had its own
full-API overhead while both compared binaries used d6; its deferral is not an
engine-version result. Consumer `28a6144` restores the measured `4f1bde7` storage
implementation while retaining the d6 engine pin.

## November 5 scope decision

The owner accepted the existing plan plus a validated FTS correctness fix and
PR #65 filtered-search cases. The layered-storage backend is not selected.
Temporary-relation diagnostics (#12) remain optional after the core gates pass,
with warning behavior agreed before implementation. Other evidence-gated features
remain deferred. The FTS correctness work uses the existing correctness exception
to scope freeze; it does not admit an unmeasured ANN redesign.

## Demand-gated system-versioning integration

Recorded 2026-09-07 under MindGraph adoption B-T2 / D2. Evaluate an indexed
current-state view alongside commit-stamped history, with defined current-side
trigger/projection behavior, history retention access paths, a history-preserving
supported backup/restore contract, and reversible enable/disable semantics.
Preserve snapshot consistency, crash recovery, erasure and existing non-temporal
query behavior.

Activation: a MindGraph pilot relation in production for at least 30 days with
system-time reads answering a named customer question, or a named external TxTime
user requiring indexed current reads. This is a feasibility proposal, not a 0.19
build commitment. Current/history separation is an option to evaluate, not a
prescribed engine architecture. No MindGraph pilot is authorized by recording
this item: a named consumer and accepted recovery contract are prerequisites.

## Historical release readiness checklist — November 5

November 5 local qualification is recorded [here](../reviews/2026-11-05-0.19-candidate.md):
warning retirement, migration/upgrade parity and optimized package checks had
progressed at immutable engine `0148693b`. At that checkpoint, the owner deferred
full E1–E3 timing runs to a dedicated quiet window. The checklist below records
that acceptance plan; the November 8 decision above supersedes its measurement
sequence. Local smoke evidence alone does not establish final artifact readiness.

The subsequent [HNSW mutation investigation](../reviews/2026-11-05-hnsw-update-investigation.md)
confirms an inherited correctness defect: removing a bridge vertex, including
the removal stage of a vector update, can disconnect surviving rows from ANN.
Both released 0.18 and the candidate reproduce it; exact base-key retrieval stays
correct and rebuild restores the tiny fixtures. Increasing ef does not repair it.
The owner subsequently explicitly selected its repair for 0.19. Track that fix
independently of optional filtered-search enhancements. The [bounded-search draft](../specs/bounded-filtered-vector-search.md)
is a prototype contract, not banked engine functionality or automatic scope growth.

These original boxes are retained as a historical checklist, not the current
readiness verdict. Final publication checks must identify their own immutable
artifact; prior release checks and current-main CI do not validate it.

The approved HNSW repair is implemented at `e606c661`; its
[local validation record](../reviews/2026-11-05-hnsw-mutation-repair.md) contains
398 library and 85 integration passes, strict Clippy, minimal compilation,
independent contract review and an extracted-crate host smoke. Old `0148693b`
artifacts remain pre-repair controls. Subsequent runtime and artifact evidence supersedes this early qualification;
the November 8 summary above records the final measurement scope.
